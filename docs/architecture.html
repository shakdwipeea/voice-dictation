Sunoto architecture

A local push-to-talk dictation daemon. Hold Ctrl+F1, speak, release, and the text lands in the focused window. One Rust binary owns the hotkey, microphone, session state, cleanup and insertion. The speech model, the LLM cleanup pass and the on-screen overlay are child processes talking newline-delimited JSON over stdin and stdout. Nothing leaves the machine.

the recording overlay: dot + level meter, 214×34, nothing else while you speak

The big picture

  1. One loop owns policydaemon.rs decides everything. The other threads are bridges that turn an OS event or a stdout line into an event on one channel.
  2. Sidecars are processesASR, LLM and overlay each speak a tiny NDJSON protocol. A crash means restart with backoff, never a daemon crash.
  3. Text in, text outDictation never executes anything. The separate System mode is fenced by a different hotkey, a different session mode, and a type system with no "run a string" variant.

Verdict

What is good

  • Small, boring core. Three third-party crates in the whole workspace: serde, serde_json, url. CoreAudio, CGEvent, Xlib and XTEST are hand-written FFI. Nothing to upgrade, nothing to audit.
  • Pure, tested state machine. sunoto-core has zero deps and encodes the invariants that bite: stale finals cannot overwrite a live session, failure always returns to Idle, ids never repeat, System results cannot reach the insert path.
  • Latency path protected by construction. Overlay writes are try_send on a bounded channel and drop instead of block. LLM warm-up runs after ASR is ready because they share the GPU. A 1-token keepalive each second stops Metal cold-ramping, which turned a 4 s prefill into 200 ms.
  • Graded failure. ASR crash → restart with 0.5 to 5 s backoff. Overlay never came up → native bubble, no respawn loop. LLM warm-up failed → dictation continues without it. Hotkey grab failed → daemon stays up, control socket still works.
  • Protocol hygiene. Every real sidecar dups stdout and points fd 1 at stderr so library chatter cannot corrupt the stream. Unparseable lines become Garbage events. Newer fields are Option with serde(default).
  • Explicit safety. Enter/Tab neutralized so a terminal never runs dictated text. Focus re-checked before insertion. System mode: no shell, no AppleScript, no Exec parsing, HTTP(S) only, every action needs a palette selection.
  • Instrumented. One log line per session with the full timing breakdown. bench and eval subcommands write JSON.

What is not good

  • daemon.rs is a 3,000 line god file. Event loop, the Wayland adapter, insertion order for three platforms, overlay management, LLM orchestration, System dispatch and the control socket all live there. The facade only abstracts X11 and macOS. Split this first.
  • Duck-typed platform layer. sunoto-desktop is a cfg re-export, not a trait. Both platform crates must export identically named types. The macOS error type is called X11Error.
  • JSON arrays of i16 for audio. 50 messages a second of 320 integers as text. Fine at 16 kHz mono, would not survive stereo or higher rates.
  • No protocol version. The handshake is health → ready. Compatibility rests on everyone remembering serde(default).
  • Clipboard differs per platform. X11 saves and restores the previous clipboard. macOS and Wayland overwrite it permanently.
  • macOS reliability is TCC folklore. The CGEventTap goes inert when the binary is rebuilt or launched from launchd. The fix is a bash login item that stays the daemon's parent. check can pass while the tap is dead. Most recurring bug in the project.
  • Transcripts logged in full at info level, every final and every polish stage. A privacy problem for a dictation tool, listed as a release blocker.
  • Python runtime sprawl. Three venvs, one built by hand, plus system Python for the mock and GTK overlay.
  • Tests stop at the process boundary. No integration test drives the real daemon. system_worker.rs has zero tests. Linux System mode never ran on a Linux desktop. Two planning docs disagree on whether System mode exists.
  • No spoken punctuation or numbers. "New line", "period", "twenty three" are not interpreted.

macOS first: path to a normal-user package

The engine is done. What a non-developer hits is permissions, warm-up, and the build-from-source install. Each step below is useful on its own and none requires the later ones.

Phase A. Code-only fixes, no Apple account needed

  1. Truthful readiness. After the tap is created, post a synthetic flagsChanged event through CGEventPost and confirm the tap callback sees it within a second. If not, display "Hotkey blocked: grant Input Monitoring to Sunoto" instead of "ready". Make check run the same probe.
  2. Warm-up state in the overlay. Show the pill with a neutral dot and "loading speech model" until the ASR sidecar is ready, and "warming polish" until the LLM is warm. A press during warm-up shows that state instead of being ignored.
  3. Clipboard restore. Read pbpaste before pbcopy, paste, wait about 300 ms for the target to consume it, then write the previous contents back. X11 already does this.
  4. Secure-field guard. Ask Accessibility for the focused element's role. If it is AXSecureTextField, refuse to insert and say "password field, text left on clipboard".
  5. Transcript-safe logs. Log length and a hash by default. Add log_transcripts: true for debugging.

Phase B. Packaging decisions the user has to make

  1. One real app bundle. Daemon, Swift overlay and a bundled Python runtime inside Sunoto.app, signed with a Developer ID and notarized. A stable signing identity is what makes TCC grants survive updates and removes the whole "grant to two paths, re-grant after rebuild" class of bugs. Needs an Apple Developer account.
  2. Bundle the Python runtime. python-build-standalone plus parakeet-mlx and llama-cpp-python wheels inside the bundle. Download the ASR model (about 600 MB) and the LLM (about 3 GB) on first run with a progress bar. Decide whether the LLM download is default or opt-in; without it the app still dictates in Fast mode.
  3. Menu bar app. Fold the Swift overlay into a small menu bar app that shows state (ready, warming, blocked, recording), opens the right permissions pane, toggles LLM polish, and opens the log. Replaces the bash login item.
  4. First-run onboarding. Walk through Microphone, Accessibility and Input Monitoring one at a time and verify each live with the probes from step 1. Never say "ready" until a synthetic press actually starts a recording.
  5. DMG plus automated release gate. Drag-to-Applications DMG. A CI job on a macOS runner that builds, signs, notarizes, launches, grants permissions with tccutil where possible, and runs the live probes.

Steps 1 to 5 are a few days of Rust and Swift with no external dependency. Steps 6 to 10 turn the project into something a normal user can install. Step 6 is the one that actually kills the recurring macOS bugs.

Protocols

One JSON object per line, tagged by type, snake_case.

ASR in
health, start_session{session_id, profile_ms}, audio_chunk{session_id, samples: [i16]}, finish_session, cancel_session
ASR out
ready{backend}, session_started, partial{text}, final{text}, error{session_id?, message}
Overlay in
show, hide, recording{elapsed_s, peak, rms, segments}, status{text}, segment, clear, system_palette{…}, dismiss_system_palette, shutdown. Palette payloads carry no paths or bundle ids by design.
Overlay out
ready, system_selection{suggestion_id}, system_cancelled
LLM in
polish{session_id, text}, warmup{texts}, shutdown
LLM out
ready{load_ms, warmup_ms}, polished{text, latency_ms, …}, polish_chunk{sequence, delta}, warmed, error
Control socket
$XDG_RUNTIME_DIR/sunoto/daemon.sock or $TMPDIR/sunoto-$USER-daemon.sock. Accepts bare press/release, trigger{mode, edge}, polish{text}, plan_system{text, dry_run: true}. This is how Hyprland keybindings reach the daemon.

System mode in five lines

Separate hotkey, off by default. Transcript → deterministic router → one of 9 typed intents, or NeedsLlm, or Rejected (multi-action input like open Chrome; rm -rf is rejected, not split). Policy today is always "present suggestions"; there is no auto-execute variant. Native resolvers (NSWorkspace + mdfind on macOS, GAppInfo + GIO on Linux) return opaque ids; the palette shows titles only; a one-time selection token is revalidated against the filesystem before NSWorkspace openURL or gio launch runs. Six capabilities: application find/open, target find/open, url.open, web.search. No shell, no AppleScript, no LLM planner connected yet.

Tests

make test runs the Rust workspace (about 230 tests, clippy with -D warnings) plus Python unittest suites: phase0 (16, tooling), phase1 (88, sidecar protocols with fake engines, no GPU), phase2 (10, corpus and stream parser), ui (8, overlay dispatch without GTK). make phase2-eval scores the deterministic pipeline against 32 scripted cases. There is no integration test of the running daemon.
