The architecture change

The daemon still does everything on one event loop, in the same order: shortcut, recording, speech engine, tidy-up rules, optional AI editor, paste. What is new sits beside that loop, not in its way:

  • A history draft that each stage fills in as the dictation moves along. This is plain memory work on the loop.
  • A hand-off queue with room for 16 records. The loop hands the finished record over with try_send, which never waits; if the queue is ever full, that record is dropped and counted.
  • A history-writer thread, the only code that touches the disk. It appends one line to the day's file and deletes day files past the retention limit, at start and once a day.
  • A sunoto-daemon history command that reads and deletes the files directly, so it works whether or not the daemon is running.

The life of a record

Every dictation that starts also ends in exactly one line, whether it was pasted or failed along the way. A test covers each ending.

Grammar model test (plan step 2)

This is the small model planned for the Improve button: Unbabel/gec-t5_small, with 60.5M parameters and an Apache-2.0 license. It was run on the M1 Pro's CPU over 91 labeled sentences: 30 with typical mistakes, 50 clean ones from the repo's test sets, and 11 technical ones with file names, links, numbers and brand names. The weights were loaded tensors-only, so the downloaded file could not run code.

MeasureResultVerdict
Mistakes fixed24 / 30Good. Misses: "Who's" → "Whose", "Then you" → "Thank you" (a mishearing), "Me and him".
Clean sentences left alone44 / 503 meaning changes, e.g. "The build is green" → "The building is green", "It is my fault" → "It was my fault". The preview and Cancel are essential.

Memory, lean load (bf16, no extra copy)~380 MB · 0.16 sAbout 350 MB of this is PyTorch itself. MLX, which Sunoto already ships, adds about 7 MB, so the estimate is roughly 150 MB on MLX. That is not measured yet.

Verdict: promising, and worth building the Improve button on, with three conditions: greedy decoding, the stricter guard rail, and an MLX runtime to meet the memory target. The meaning changes are the real risk: they are rare, but the guard rails can't see them, so Improve must always preview before it replaces anything. A larger T5-base model should be tried if real dictations show too many of them.

Fix and Improve (plan step 3)

After each paste, a small chip appears under the pill for a few seconds. The pill's own check-mark animation is unchanged.

  • Fix opens a box for what the dictation should have said. It's saved as a note on that dictation in the history, and the text in the app is not changed.
  • Improve asks a new helper process for a corrected version, checks it, shows it with the changed words highlighted, and Replace swaps it in.

The architecture change is one more helper process beside the speech engine. It's started on demand, loads the model only while it's needed, and exits when idle.
